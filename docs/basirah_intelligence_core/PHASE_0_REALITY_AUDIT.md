## First five highest-risk defects (could still produce an incorrect recommendation today)

1. **No liquidity gate.** A thinly-traded stock with a technically "clean" setup can still reach BUY/STRONG_BUY and TOP_BUY — there is no traded-value/volume floor anywhere in the pipeline. This is the most direct remaining path to another 1020-class embarrassment (a real setup that is not actually tradeable at size).
2. **TOP_BUY sorts eligible candidates by `final_score` alone**, even after this session's gate fix. The gate guarantees every entry is a *defensible* trade; it does not guarantee the *best* one is ranked first, since risk/reward, evidence completeness, and liquidity aren't part of the sort key.
3. **No sector-aware fundamental model.** Banks, insurers, REITs, and industrials are scored with one generic model; symbol 1113's fundamental score going `N/A` in the last live run is a direct, already-observed symptom.
4. **TASI/benchmark data is entirely absent as a time series**, so no recommendation can honestly claim market-relative strength — currently handled correctly (disclosed `NOT_EVALUATED`, never silently assumed), but it means every recommendation is single-stock-only evidence with no market-regime context, which is a real analytical weakness, not just a labeling one.
5. **Single fixed weighted blend, no adversarial/conflict-detection stage.** `AIDecisionEngine` produces one number from one formula; there is no step that independently reasons about technical vs. fundamental vs. liquidity conclusions, detects disagreement between them, or builds a bear case before publishing a BUY. The publication gate added this session rejects on a few concrete failure signatures (bad risk/reward, missing data) but does not perform the structured multi-stage reasoning Phase 6 specifies.

## Milestone sequence for this branch

Given the realistic scope of the full mandate (multi-week), milestones are ordered by defensibility-per-hour, starting with what most directly reduces the risk of a bad recommendation reaching tomorrow's 10:00 AM live run, then continuing incrementally in later sessions:

1. **M1 (this session): liquidity gate** — add a minimum-liquidity check to `publication_gate.py`, closing highest-risk defect #1.
2. **M2 (this session, time permitting): TOP_BUY ranking beyond raw score** — incorporate risk/reward and evidence completeness into the sort key, addressing defect #2, without a full Phase 6 rewrite.
3. **M3 (follow-up session): sector-aware fundamental scoring** for banks/insurers/REITs, closing defect #3 and the 1113/1263/1295/2315 gap.
4. **M4 (follow-up session): Arabic name search/resolve endpoint** — concrete, bounded, high product value, reuses the existing `name_ar` column.
5. **M5+ (follow-up sessions): the larger items** — multi-timeframe engine, pattern recognition, chart overlays, conversational analyst, TASI ingestion (external-data-source decision required first) — each is its own multi-day effort and will be executed incrementally with the same inspect→implement→test→commit→push discipline, not simulated in one pass.
