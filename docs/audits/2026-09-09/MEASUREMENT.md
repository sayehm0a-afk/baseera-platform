# سجل الأدلة ومنهجية القياس

## الموجود وما ينقص

DecisionV2Snapshot يحتوي معرفًا ورمزًا ووقت قرار وquote_timestamp وengine_sha/config_hash ونسخة تحليل ومنطقة دخول وأهداف ووقف ومدة وشروط وأسباب وتحذيرات وجودة بيانات. حقول قديمة قد تكون NULL؛ لا يعاد ملؤها بقيم النسخة الحالية. DecisionV2Outcome فريد لكل snapshot، ويحمل دخولًا ونتيجة وأوقات فحص واستقلال الإشارة. الانتهاء متصل بـ due_at في outcome، ولا يوجد إثبات هنا أن كل قرار معروض له سجل محفوظ كامل وأحداث انتقال غير قابلة للتعديل.

سجل الحد الأدنى المطلوب لاحقًا: معرف الحدث، معرف القرار، الحالة السابقة/الجديدة، وقت الحدث ووقت تسجيله، مصدر الأسعار/الشمعة، نسخة المقيم، سبب الانتقال، معرف تصحيح ملحق عند الحاجة. لا تعديل للتوصية الأصلية بعد معرفة النتيجة. إضافة هذا السجل لم تُنفذ بترحيل في هذه الدفعة.

## تفسير الحالات القائمة

| الحالة | المعنى المحاسبي |
|---|---|
| PENDING + entry_triggered=false | تنتظر التفعيل |
| PENDING + entry_triggered=true | تفعّلت ولم تنتهِ |
| TARGET_1/2/3_HIT | لمس هدف في نموذج التقييم؛ ليس إثبات تنفيذ تداول |
| STOP_LOSS_HIT | وقف بعد التفعيل في النموذج |
| ENTRY_NEVER_TRIGGERED | انتهت النافذة دون دخول |
| INVALIDATED | إبطال قبل الدخول، ليس خسارة صفقة منفذة |
| EXPIRED | انتهاء الأفق بعد التفعيل بحسب المنطق الحالي |
| PARTIAL | هدف ووقف في شمعة واحدة؛ ترتيب ملتبس، وليس فوزًا أو خسارة مثبتة |
| DATA_UNAVAILABLE | تعذر التقييم بسبب البيانات |
| CANCELLED | إلغاء يحتفظ به ولا يحول إلى نجاح |

المقيم الحالي يستخدم لمس منطقة الدخول وentry_zone_high كافتراض سعر، وليس أمرًا منفذًا. الوصول لأول هدف ينهي التقييم؛ لا يجوز استنتاج خروج جزئي أو العائد الكامل للهدف الثالث من ذلك. حالات التعادل لا يُخترع ترتيبها. حدود التقويم وسيولة التنفيذ والانزلاق والتكاليف تمنع تقديم النتائج كأرباح فعلية.

## بروتوكول الأداء المقترح قبل جمع العينة

هذا بروتوكول قياس مقترح خارج اعتماد قواعد القرار، وليس تغييرًا منشورًا:

1. تثبيت SHA/config ومصدر/توقيت البيانات، فصل كل أفق زمني، وعدم مزج المحرك القديم والجديد أو بيانات مصطنعة.
2. وحدة القياس إشارة مستقلة موثقة؛ الاستمرارات تُعرض وتُستبعد من العينة المستقلة، والحالات مجهولة الاستقلال تُحصى منفصلة.
3. تحديد نافذة التفعيل مسبقًا؛ لا لمس قبل الإصدار، ولا افتراض ترتيب أحداث الشمعة. استخدم بيانات أدق مرخصة أو أبق الحالة ملتبسة.
4. تحديد خروج واحد أو خطة جزئية ثابتة وتكاليف ورسوم وانزلاق وسيولة قبل الاطلاع على النتائج؛ الاحتفاظ بالإصدارات المتعاقبة للمنهجية.
5. معدل النجاح: الصفقات المستقلة المتفعلة والمغلقة بصافي عائد موجب / جميع الصفقات المستقلة المتفعلة والمغلقة والقابلة للتقييم وفق نموذج التنفيذ المعتمد. عداد الحالات الملتبسة/غير المتفعلة/غير القابلة للتقييم منفصل وبارز، مع حساسية محافظة لأثر الغائب؛ لا إسقاطها بلا بيان.
6. عرض العدد والفترة ومتوسط الربح والخسارة والعائد المتوقع وصافي التكاليف وأطول سلسلة خسائر. العائد المتوقع هنا متوسط صافي العوائد المؤهلة، وليس توقعًا مضمونًا للمستقبل.
7. أكبر تراجع وعائد المحفظة لا يحسبان دون رأس مال وأحجام مراكز وحدود تزامن وقواعد إعادة استثمار ونموذج قيمة يومية. تبقى القيم غير متاحة حتى اعتماد ذلك.
8. درجة الأدلة ليست احتمالًا؛ المعايرة تتطلب عينة زمنية مستقلة وتقييم موثوقية/خطأ معايرة وفواصل ثقة مناسبة. لا معيار مسبق مثل 95% نجاح.
9. تجربة أي تحسين لاحقًا على تقسيم زمني خارج التطوير ومتابعة أمامية، بنفس المصدر والتكاليف ونطاق الأسهم. معايير مقارنة مسبقة: العائد والتراجع والتغطية وعدد الفرص معًا. لم تُنشأ نسخة تجريبية لمحرك القرار لأن خط البيانات والعينة لم يثبتا.

## أداة التقرير المنفذة

`scripts/audit/daily_evidence_report.py` يقرأ جداول V2 دون استدعاء المحركات أو المصدر. يحدد يوم الإصدار بتوقيت الرياض، ويعرض عدد القرارات والمخرجات والتفعيلات والاستمرارات والحالات وغياب وقت السعر/تأكيد البيانات الحقيقية، ويفصل نسخة المحرك والإعدادات. يرفض تكرار ربط outcome حتى لا يضاعف العد، ويرفض استبدال ملف موجود.

النتائج تخص **قرارات صدرت في اليوم المختار كما تُرى نتائجها وقت تشغيل التقرير**؛ ليست أحداث ذلك اليوم ولا إعادة بناء تاريخية لما كان معروفًا فيه. معاملات PostgreSQL للقراءة فقط ومعزولة repeatable read بمهلة 30 ثانية؛ هذا المسار لم يُختبر على PostgreSQL هنا. اختبارات SQLite الأربعة نجحت، ومنها حدود منتصف الليل السعودي والالتباس والعد المكرر ومنع الاستبدال.

حقول الربحية والتراجع ونسبة النجاح في التقرير `null` عمدًا؛ لا يجمع التقرير درجات داخلية ويطلق عليها نجاحًا. المثال `evidence/daily-report-example.json` مولّد من fixture اختبار معلن، وليس نتائج السوق.

**لم تُشغّل متابعة آلية ولم تُفعّل مهمة دورية.** يلزم اتصال قراءة مصرح بقاعدة فعلية، وجهة حفظ، واختبار انتهاء المهمة وفشلها والتنبيه، ثم توثيق أول تشغيل وآخر بيانات صالحة. لا يكفي إنشاء cron أو وجود ملف لادعاء عمل متابعة يومية. يضاف إلى التشغيل المعتمد مستقبلًا: حالة المزود، آخر quote صالح، عدد الشركات والفجوات، آخر مهمة ناجحة ومدة التشغيل والأخطاء؛ لم تُخترع هذه القيم في التقرير الحالي.
